# todoアプリ 仕様書 v0.1

- 版: v0.0(ただの `todo` アプリ)と v0.1(+通知)の2段で作る。本書は v0.1 を目標とする。
- 名称: `schedule_manager`(2026-11-27 採決。前アプリと同名の継続)。application id は io.github.sh_sunfaded.schedulemanager(前アプリと同一のため、上書きインストールできる)。
- 経緯: 2026-11-27 の本人宣言で、`schedule_manager` の構想(睡眠帯・中継・MCP 統合)は一旦将来構想へ退け、まず単純な `todo` アプリを作ることとした。将来構想の正本は仕様書 v1.0(Canvas〈reminder-todo-spec-v1〉)。

## 1. 目的

- まず動く `todo` アプリを作る。v0.1 の完成の判定は「実機で、自分の `todo` の期限通知と任意時刻のリマインダが届くこと」とする。
- 生活リズムとの統合(睡眠帯・中継 `API`・`MCP`)は本書の範囲外とし、v0.1 が固まってから改めて採決する。

## 2. 版の定義

- v0.0(ただの `todo` アプリ): `todo` の登録・一覧・編集・完了・削除と期限(任意)。通知は無い。
- v0.1(+通知): v0.0 に加えて、期限の時刻の通知と、任意時刻のリマインダ発火。

## 3. 機能(v0.0)

- 追加: `title`、`note`(任意)、`due_at`(任意、分まで)。
- 一覧: 未完了が上、完了は下に折り畳む。未完了は期限の近い順。
- 編集・完了・削除(削除は確認付き)。
- 状態は `active` / `done` の2つとし、他の状態を持たない。
- `UI` は素朴に作る(装飾を作り込まない)。

## 4. 機能(v0.1 通知)

- 期限通知: `due_at` が設定された `todo` は、その時刻に通知を出す。
- リマインダ: 任意の時刻(分まで)を `todo` に付けられる。1つの `todo` に複数可。各1回限りとし、繰り返しは将来に置く。
- 発火の信頼性: `AlarmManager`(exact)で発火し、再起動後とアプリ更新後に予約を復帰する。`WorkManager` は定期の再登録の保険とする。
- 通知をタップするとアプリを開き、該当の `todo` を表示する。
- 期限・リマインダの編集・削除には、発火予約が追随する。
- 文言は素朴な1行とする。典型例は実装の `golden` で正本化する。
- 通知は常に標準の音で出す(夜間の音なし設定は持たない。まず素朴に始め、様子を見てから改めて採決する)。
- 通知の許可(`POST_NOTIFICATIONS`)を要求する。拒否されても一覧等の機能は落とさない。

## 5. データモデル

```
task
  { id, title, note?, due_at?, status(active|done), created_at, updated_at, done_at? }

reminder
  { id, task_id, fire_at, fired_at? }
```

- 発火済みは `reminder.fired_at` で記録し、別の `log` は持たない。
- `todo` を削除したら、付けられた `reminder` も消す。

## 6. アーキテクチャ・技術

- `Android` ネイティブ(`Kotlin` + Jetpack `Compose` + `Room`)。`UI` はアプリ内のみで、Web は作らない。
- 次回発火の計算は純関数に置き、`JUnit` で検査する。文言の典型例は `golden` で固定する。
- タイムゾーンは `Asia/Tokyo` 固定。
- 署名鍵は専用 `keystore` を `repo` 外で管理し、gradle は local.properties 経由で読む。

## 7. 運用・規約(前プロジェクトからの継承)

- 配布は実機直接(本人の端末への `APK` サイドロード)。ストア公開はしない。
- `allowBackup` は `false`。
- CI: lint と単体テストを載せる。機密語 0・簡体字 0 の文言家規を初回から適用する。
- 実装は Claude Code への委任とし、1マイルストーン1往復で回す。検収は報告書と `repo` 実体の照合で行う。

## 8. ロードマップ・検収

- v0.0: 一覧・登録・編集・完了・削除・期限と、CI 緑。実機で自分の `todo` を登録して使える状態。
- v0.1: 期限通知・リマインダ・再起動後の復帰・通知タップ。検収は実機で自分の `todo` による1日運用(期限通知と任意時刻リマインダが届き、再起動後も復帰すること)。
- 将来: 睡眠帯・中継 `API`・`MCP` の統合は、将来構想の仕様書(Canvas〈reminder-todo-spec-v1〉)に退けてある。v0.1 が固まった後に改めて採決する。

- 未決は無し。名称(`schedule_manager`)と通知の音(常に標準の音)は 2026-11-27 に採決済み。期限切れの扱い(表示・自動整理)は v0.1 では作り込まないと確定済み(将来で再採決)。
